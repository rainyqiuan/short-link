# 高并发短链平台 · 接口设计

> 约定：所有接口返回 **HTTP 200 + 统一响应体**，业务成败看 `code`。
> **唯一例外**是 `GET /{code}` 跳转接口——它要返回 HTTP `302` + `Location` 头，不走统一响应体。

---

## 一、通用约定

### 1. 基础信息

| 项 | 值 |
|---|---|
| 服务地址 | `http://localhost:8080` |
| 接口前缀 | `/api` |
| 短链域名 | `http://s.xx.com/`（配置项 `app.short-domain`，本地可用 `http://localhost:8080/`） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 字符编码 | UTF-8 |
| 字段命名 | 请求与响应统一 **小驼峰** |

### 2. 统一响应体

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "3f2a91c4b7e84d0f"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 表示成功，非 `0` 见错误码表 |
| `message` | string | 失败原因（可直接展示给用户） |
| `data` | object / array / null | 业务数据 |
| `traceId` | string | 请求追踪 ID，排查时让用户提供这个值 |

### 3. 错误码表

**分段规则**：`0` 成功 / `400xx` 客户端问题（参数、短码、状态冲突）/ `500xx` 服务端问题。
**业务码与 HTTP 码解耦**——同一个业务码在不同接口可能对应不同 HTTP 码，不要互相推导。

| code | 含义 | 触发场景 | HTTP |
|---|---|---|---|
| `0` | 成功 | - | 200 |
| `40001` | 参数错误 | 通用兜底（校验失败） | 200 |
| `40002` | 参数格式错误 | 类型转换失败等 | 200 |
| `40003` | 短码格式非法 | `customCode` 不满足 4-16 位字母数字 | 200 |
| `40004` | 过期时间非法 | `expireTime` 早于当前时间 | 200 |
| `40005` | 短码不存在 | 查询/禁用不存在的短码 | 200 |
| `40006` | 短码已被占用 | 自定义短码冲突 | 200 |
| `40007` | 短链已被禁用 | 跳转时 `status = 0` | 410 |
| `40008` | 短链已过期 | 跳转时 `expire_time` 已过 | 410 |
| `40009` | 触发限流 | 超过 QPS 阈值 | 200（或 429） |
| `50000` | 系统异常 | 未捕获异常（不暴露堆栈） | 200 |
| `50001` | 依赖服务不可用 | MySQL / Redis 连接失败 | 200 |

> 说明：业务错误一律走 **HTTP 200 + `code`**，便于前端统一拦截；**只有跳转接口**用真实 HTTP 状态码（302/404/410），因为浏览器要靠它跳转。跳转接口失败时也会把 `code` 写进响应体（返回一个简单 HTML 页），方便排查。
>
> **为什么不让业务码等于 HTTP 码**：业务码会越加越多（`40003`/`40004` 都属于 400 语义但前端要分开提示），同号很快不够用；而且同一个业务码在跳转接口是 410、在管理接口是 200，绑死在一起会互相牵制。

## 三、接口详情

### 1. 创建短链

`POST /api/link`

**请求体**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `originUrl` | string | 是 | ≤ 2048（必须由 `@Size` 强制），必须 http/https | 原始长链接 |
| `customCode` | string | 否 | 4-16 位，仅 `[0-9a-zA-Z]`，**大小写不敏感**；**仅在该 URL 首次创建时生效** | 自定义短码，不填则系统发号 |
| `expireTime` | string | 否 | 格式 `yyyy-MM-dd HH:mm:ss`，必须晚于当前时间 | 过期时间，不填为永久 |

```json
{
  "originUrl": "https://example.com/very/long/path?a=1&b=2",
  "customCode": null,
  "expireTime": "2026-12-31 23:59:59"
}
```

**响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "shortCode": "aB3xK9",
    "shortUrl": "http://s.xx.com/aB3xK9",
    "originUrl": "https://example.com/very/long/path?a=1&b=2",
    "expireTime": "2026-12-31 23:59:59",
    "createTime": "2026-09-20 16:00:00"
  },
  "traceId": "3f2a91c4b7e84d0f"
}
```

**幂等规则（重点，面试会问）**

- 同一条 `originUrl` 重复提交 → 返回**同一个** `shortCode`，不新建记录。
- 实现：对 `originUrl` 取 MD5 做唯一索引；查不到才创建，并发时靠唯一索引兜底并捕获 `DuplicateKeyException`，捕获后重新查询并返回已有短码。

> **实现提示 0（并发幂等：已修复，2026-09-26 实测验收）**：曾经的并发实测（8 线程同时提交同一 URL）是 **1 个成功、7 个失败**（6 个 `DeadlockLoserDataAccessException`、1 个 `50000`）——数据始终正确（库里只有 1 行），但**"并发时返回已有短码"这条承诺没有兑现**。两处独立根因：① MySQL 默认 **REPEATABLE-READ**，事务快照在第一次读时固定，"撞键后回查 md5"在**同事务内**永远看不见并发赢家（实测：裸读 = 0，加锁读 `FOR SHARE` = 1）→ 归因错误 → 换号重试；② **重试发生在同一个事务里**，而 duplicate-key 已给冲突记录上了共享锁，同事务再插同一索引就是在请求锁升级 → 死锁。
>
> 现已修复并复验（详见 `docs/05` 三之三十二）：外层 `createShortLink` **不带 `@Transactional`**、只负责重试；内层每轮尝试由 `TransactionTemplate` 包成**一个独立事务**；归因改为**读异常 message 里的索引名**（`Duplicate entry 'x' for key 't_short_link.uk_origin_url_md5'`）；死锁由 `catch (ConcurrencyFailureException)` 接住后在新事务里重试。**实测 2 / 4 / 8 线程同时提交同一 URL → 全部返回同一短码、库里 1 行、零死锁、零 `50000`。**

**幂等优先级（必须写进接口文档的产品语义）**

| 场景 | 行为 | 说明 |
|---|---|---|
| 同一 URL 第二次**不传** `customCode` | 返回首次创建的短码 | 标准幂等 |
| 同一 URL 第二次**传了** `customCode` | **返回首次创建的短码，`customCode` 被忽略** | 幂等判断在自定义短码处理**之前**，请求不会走到自定义码那一层 |

> **语义：一个 URL 只有一个短码，以首次创建时为准（先到先得）。**
> 客户端若想"换个短码重试"，必须**先换 `originUrl`**，否则永远拿到同一个码。

**去重索引的持有规则（另一条必须写明的产品语义）**

唯一索引 `uk_origin_url_md5` 建在**函数索引** `IF(del_flag = 0, origin_url_md5, NULL)` 上，因此：

| 旧记录状态 | 该 URL 还能重新创建吗 |
|---|---|
| 正常 | 幂等返回旧短码 |
| **逻辑删除** | ✅ 能（索引已释放，`del_flag=1` 时索引键为 `NULL`） |
| **禁用**（`status=0`） | ❌ **不能**，永远返回 `40007` |
| **已过期** | ❌ **不能**，永远返回 `40008` |

> **想让一个被禁用/过期的 URL 重新建链，必须先把旧记录逻辑删除。**
> 之所以不能"过期即释放"：函数索引只能引用**确定性**列，`expire_time > NOW()` 会被 MySQL 直接拒绝（`ERROR 3758`）。过期清理留给定时任务（M5）。

**错误场景**

| 场景 | code |
|---|---|
| `originUrl` 为空 / 非 http(s) | `40001` |
| `expireTime` 格式非法 | `40002` |
| `customCode` 格式非法 | `40003` |
| `expireTime` 早于当前时间 | `40004` |
| `customCode` 已被占用 | `40006` |
| 该 URL 已有记录且**被禁用** | `40007` |
| 该 URL 已有记录且**已过期** | `40008` |
| 触发限流 | `40009` |

> **实现提示 1（`40002`）**：需要全局异常处理器显式翻译 **`HttpMessageNotReadableException`** —— DTO 字段是 `LocalDateTime`，格式错误发生在 Jackson 反序列化阶段，抛的不是 `MethodArgumentNotValidException`。未翻译时会落到兜底，变成 `50000 系统异常`（实测确认）。
>
> **实现提示 2（`40003` / `40004`）**：`@Pattern` / `@Future` 失败抛的都是 `MethodArgumentNotValidException`，处理器必须**按 `FieldError.getField()` 分流**才能回出这两个码；否则所有字段级校验失败一律 `40001`（实测确认，`40003`/`40004` 曾是死枚举）。码值请引用 `ResultCode` 而不是写裸数字。
>
> **实现提示 3（读写格式必须一致）**：`expireTime` 的**入参格式与出参格式必须是同一个**。DTO 上必须显式声明 `@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")` —— 不写则 Jackson 退化为 ISO 8601（要求 `T` 分隔），而 converter 输出用的是空格分隔，结果就是"用户拿到什么、原样回传就被拒"。实测：空格格式 → `40002`，ISO 格式 → `code=0`；且 `40004` 只有在 ISO 格式下才可达（空格格式在反序列化阶段就失败了，走不到 `@Future`）。
>
> **实现提示 4（协议白名单）**：`40001` 承诺"非 http(s)"要被拒，但 **`@URL` 的默认范围包含 `ftp` 和 `file`**（实测 `ftp://...` 与 `file:///C:/Windows/win.ini` 都能建链落库）。限定协议请用 `@URL(regexp = "^(http|https)://.+$")`（实测可同时拒掉 `ftp` / `file` / 空 host），不要单独依赖 `@URL` 默认行为，也不要用 `@URL(protocol = "https?")`（`protocol` 不解析正则，会把 `http` 一起误拒）。

> **实现提示 5（长度上限必须由代码强制）**：字段表里的"≤ 2048"不写校验就是一句空话。实测（加 `@Size` 之前）：`originUrl` 传 **2048** 字符 → 成功；传 **2049 / 5000** 字符 → **`50000 系统异常`**（`@URL` 只看"长得像不像 URL"、不看长度 → 放行 → `insert` 时 MySQL 严格模式报 `Data too long` → `DataIntegrityViolationException` → 落到兜底）。**现已加 `@Size(max = 2048)`，实测 2049 / 5000 都回 `40001 原始URL长度不能超过2048`，库里 0 行。** 注意：service 层仍无长度校验（直调传 2049 → `DataIntegrityViolationException`），排到 M5 补。**凡字段表里写了上限/范围，都要能指出是哪一行代码在守它。**

> **实现提示 6（可选字段的"空串"语义，待统一）**：`customCode` 与 `expireTime` 都是可选字段，但**对空串的待遇相反**（实测）：`expireTime: ""` → 被 Jackson 转成 `null` → **成功**（视为未填）；`customCode: ""` → **`40003 短码必须为4-16位`**（视为填错）。而 service 层用 `StringUtils.hasText` 判空，`""` 与 `"   "` 都算"未填" → 走发号。**同一个输入在两层得到相反判断**，前端表单留空直接提交会白白拿到 `40003`。建议正则放宽为 `^(|[0-9a-zA-Z]{4,16})$`（空串 = 未填；纯空白仍拒）。

> **实现提示 7（短码大小写不敏感）**：库表排序规则是 `utf8mb4_0900_ai_ci`，`uk_short_code` **把 `ABC` 与 `abc` 视为同一个短码**。实测：建了 `CaseA99150` 之后，再用 `casea99150` 建另一个 URL → `40006 已被占用`。这不影响正确性（前置查询与唯一索引口径一致），但**产品语义要写清楚**：`s.xx.com/ABC` 与 `s.xx.com/abc` 指向同一条链接。不建议改成区分大小写 —— 短链常被手输 / 截图识别，大小写容错是优点。

### 2. 短链跳转

`GET /{code}`

- **成功**：HTTP `302`，`Location: {originUrl}`，并异步记录一次访问（不阻塞跳转）。
- **短码不存在**：HTTP `404` + 友好页面（响应体里带 `code = 40005`）。
- **已过期 / 已禁用**：HTTP `410`（`code = 40008` / `40007`）。

> **设计要点**：302（临时重定向）而不是 301（永久重定向）。
> 因为 301 会被浏览器**永久缓存**，之后统计不到访问量，也无法修改跳转目标。
> 这是这个项目里最容易被问倒的一个点，务必记住。

**性能要求**：跳转接口是**读多写极少**，必须走 Redis 缓存，目标 QPS ≥ 5000（W6 压测验证）。

### 4. 启用 / 禁用短链

`PUT /api/link/{code}/status`

**请求体**

```json
{ "status": 0 }
```

`status`：`1` 启用，`0` 禁用。禁用后跳转返回 HTTP `410` + `code = 40007`。

> 禁用后要**主动删除 Redis 缓存**，否则缓存里还是旧状态。

---

### 5. 逻辑删除短链

`DELETE /api/link/{code}`

- 置 `del_flag = 1`，不物理删除（保留统计数据）。
- **同步删除 Redis 缓存**。

  "pageSize": 10,

## 四、核心链路（照着实现）

### 创建短链

```
POST /api/link
  → 参数校验（URL 格式、长度、过期时间）
  → 计算 originUrl 的 MD5
  → 查 t_short_link（命中则直接返回已有短码）      ← 幂等
  → 未命中：发号（Redis INCR / 号段）
  → Base62 编码得到 shortCode
  → 写入 t_short_link
  → 返回 shortUrl
```

### 跳转（W2 实现）

```
GET /{code}
  → Redis 查 short_code → origin_url
      ├─ 命中 → 校验状态/过期 → 302 跳转
      └─ 未命中 → 查 MySQL
            ├─ 不存在 → 404
            └─ 存在 → 回写 Redis（带随机 TTL）→ 302 跳转
  → 异步记录访问日志（线程池 / MQ，不阻塞跳转）
```

## 五、非功能性要求（W5-W7 逐步满足）

| 项 | 要求 | 落地阶段 |
|---|---|---|
| 限流 | 单 IP 创建接口 20 次/分钟；跳转接口按短码 5000 QPS | W5 |
| 缓存 | 短码 → 长链，TTL 24h + 随机抖动（防雪崩） | W2 |
| 缓存穿透 | 布隆过滤器拦截不存在的短码 | W3 |
| 日志 | 请求日志含 `traceId`，异常日志带堆栈 | W7 |
| 监控 | `/actuator/health`、`/actuator/metrics` 可访问 | W7 |
| 敏感信息 | 不把堆栈返回给前端 | W1 |
