# 高并发短链平台 · 接口设计

> 约定：所有接口返回 **HTTP 200 + 统一响应体**，业务成败看 `code`。
> **唯一例外**是 `GET /{code}` 跳转接口——它要返回 HTTP `302` + `Location` 头，不走统一响应体。

---

## 一、通用约定

### 1. 基础信息

| 项 | 值 |
|---|---|
| 服务地址 | `http://localhost:8080` |
| 接口前缀 | `/api` |
| 短链域名 | `http://s.xx.com/`（配置项 `app.short-domain`，本地可用 `http://localhost:8080/`） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss` |
| 字符编码 | UTF-8 |
| 字段命名 | 请求与响应统一 **小驼峰** |

### 2. 统一响应体

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "traceId": "3f2a91c4b7e84d0f"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `0` 表示成功，非 `0` 见错误码表 |
| `message` | string | 失败原因（可直接展示给用户） |
| `data` | object / array / null | 业务数据 |
| `traceId` | string | 请求追踪 ID，排查时让用户提供这个值 |

### 3. 错误码表

**分段规则**：`0` 成功 / `400xx` 客户端问题（参数、短码、状态冲突）/ `500xx` 服务端问题。
**业务码与 HTTP 码解耦**——同一个业务码在不同接口可能对应不同 HTTP 码，不要互相推导。

| code | 含义 | 触发场景 | HTTP |
|---|---|---|---|
| `0` | 成功 | - | 200 |
| `40001` | 参数错误 | 通用兜底（校验失败） | 200 |
| `40002` | 参数格式错误 | 类型转换失败等 | 200 |
| `40003` | 短码格式非法 | `customCode` 不满足 4-16 位字母数字 | 200 |
| `40004` | 过期时间非法 | `expireTime` 早于当前时间 | 200 |
| `40005` | 短码不存在 | 查询/禁用不存在的短码 | 200 |
| `40006` | 短码已被占用 | 自定义短码冲突 | 200 |
| `40007` | 短链已被禁用 | 跳转时 `status = 0` | 410 |
| `40008` | 短链已过期 | 跳转时 `expire_time` 已过 | 410 |
| `40009` | 触发限流 | 超过 QPS 阈值 | 200（或 429） |
| `50000` | 系统异常 | 未捕获异常（不暴露堆栈） | 200 |
| `50001` | 依赖服务不可用 | MySQL / Redis 连接失败 | 200 |

> 说明：业务错误一律走 **HTTP 200 + `code`**，便于前端统一拦截；**只有跳转接口**用真实 HTTP 状态码（302/404/410），因为浏览器要靠它跳转。跳转接口失败时也会把 `code` 写进响应体（返回一个简单 HTML 页），方便排查。
>
> **为什么不让业务码等于 HTTP 码**：业务码会越加越多（`40003`/`40004` 都属于 400 语义但前端要分开提示），同号很快不够用；而且同一个业务码在跳转接口是 410、在管理接口是 200，绑死在一起会互相牵制。

## 三、接口详情

### 1. 创建短链

`POST /api/link`

**请求体**

| 字段 | 类型 | 必填 | 约束 | 说明 |
|---|---|---|---|---|
| `originUrl` | string | 是 | ≤ 2048，必须 http/https | 原始长链接 |
| `customCode` | string | 否 | 4-16 位，仅 `[0-9a-zA-Z]` | 自定义短码，不填则系统发号 |
| `expireTime` | string | 否 | 必须晚于当前时间 | 过期时间，不填为永久 |

```json
{
  "originUrl": "https://example.com/very/long/path?a=1&b=2",
  "customCode": null,
  "expireTime": "2026-12-31 23:59:59"
}
```

**响应**

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "shortCode": "aB3xK9",
    "shortUrl": "http://s.xx.com/aB3xK9",
    "originUrl": "https://example.com/very/long/path?a=1&b=2",
    "expireTime": "2026-12-31 23:59:59",
    "createTime": "2026-09-20 16:00:00"
  },
  "traceId": "3f2a91c4b7e84d0f"
}
```

**幂等规则（重点，面试会问）**

- 同一条 `originUrl` 重复提交 → 返回**同一个** `shortCode`，不新建记录。
- 实现：对 `originUrl` 取 MD5 做唯一索引；查不到才创建，并发时靠唯一索引兜底并捕获 `DuplicateKeyException`，捕获后重新查询并返回已有短码。

**错误场景**

| 场景 | code |
|---|---|
| `originUrl` 为空 / 非 http(s) | `40001` |
| `customCode` 格式非法 | `40003` |
| `customCode` 已被占用 | `40006` |
| `expireTime` 早于当前时间 | `40004` |
| 触发限流 | `40009` |

---

### 2. 短链跳转

`GET /{code}`

- **成功**：HTTP `302`，`Location: {originUrl}`，并异步记录一次访问（不阻塞跳转）。
- **短码不存在**：HTTP `404` + 友好页面（响应体里带 `code = 40005`）。
- **已过期 / 已禁用**：HTTP `410`（`code = 40008` / `40007`）。

> **设计要点**：302（临时重定向）而不是 301（永久重定向）。
> 因为 301 会被浏览器**永久缓存**，之后统计不到访问量，也无法修改跳转目标。
> 这是这个项目里最容易被问倒的一个点，务必记住。

**性能要求**：跳转接口是**读多写极少**，必须走 Redis 缓存，目标 QPS ≥ 5000（W6 压测验证）。

---

### 3. 查询短链详情

`GET /api/link/{code}`

**响应 `data`**

```json
{
  "shortCode": "aB3xK9",
  "shortUrl": "http://s.xx.com/aB3xK9",
  "originUrl": "https://example.com/very/long/path?a=1&b=2",
  "status": 1,
  "expireTime": "2026-12-31 23:59:59",
  "createTime": "2026-09-20 16:00:00",
  "totalPv": 1234
}
```

错误：短码不存在 → `40005`。

---

### 4. 启用 / 禁用短链

`PUT /api/link/{code}/status`

**请求体**

```json
{ "status": 0 }
```

`status`：`1` 启用，`0` 禁用。禁用后跳转返回 HTTP `410` + `code = 40007`。

> 禁用后要**主动删除 Redis 缓存**，否则缓存里还是旧状态。

---

### 5. 逻辑删除短链

`DELETE /api/link/{code}`

- 置 `del_flag = 1`，不物理删除（保留统计数据）。
- **同步删除 Redis 缓存**。

---

### 6. 分页查询列表

`GET /api/link/page?pageNum=1&pageSize=10&keyword=example&startTime=&endTime=`

**响应 `data`**

```json
{
  "total": 128,
  "pageNum": 1,
  "pageSize": 10,
  "list": [
    {
      "shortCode": "aB3xK9",
      "shortUrl": "http://s.xx.com/aB3xK9",
      "originUrl": "https://example.com/...",
      "status": 1,
      "totalPv": 1234,
      "createTime": "2026-09-20 16:00:00"
    }
  ]
}
```

- `keyword` 对 `origin_url` 做模糊匹配（**注意：`origin_url` 没有索引，模糊查询会全表扫，这是已知取舍，要能讲清**）。
- `pageSize` 上限 100，防止被拖库。

---

### 7. 查询访问统计

`GET /api/link/{code}/stats?startDate=2026-09-01&endDate=2026-09-20`

**响应 `data`**

```json
{
  "shortCode": "aB3xK9",
  "totalPv": 1234,
  "totalUv": 567,
  "items": [
    { "statDate": "2026-09-19", "pv": 320, "uv": 145 },
    { "statDate": "2026-09-20", "pv": 280, "uv": 120 }
  ]
}
```

- 数据来源：`t_link_stats_daily`（聚合表），**不查明细表**。
- `startDate`/`endDate` 跨度上限 90 天。

---

### 8. 批量创建（可选）

`POST /api/link/batch`

**请求体**：`{ "urls": ["https://a.com", "https://b.com"] }`
**响应**：逐条返回成功 / 失败，不因单条失败而整体回滚。

## 四、核心链路（照着实现）

### 创建短链

```
POST /api/link
  → 参数校验（URL 格式、长度、过期时间）
  → 计算 originUrl 的 MD5
  → 查 t_short_link（命中则直接返回已有短码）      ← 幂等
  → 未命中：发号（Redis INCR / 号段）
  → Base62 编码得到 shortCode
  → 写入 t_short_link
  → 返回 shortUrl
```

### 跳转（W2 实现）

```
GET /{code}
  → Redis 查 short_code → origin_url
      ├─ 命中 → 校验状态/过期 → 302 跳转
      └─ 未命中 → 查 MySQL
            ├─ 不存在 → 404
            └─ 存在 → 回写 Redis（带随机 TTL）→ 302 跳转
  → 异步记录访问日志（线程池 / MQ，不阻塞跳转）
```

## 五、非功能性要求（W5-W7 逐步满足）

| 项 | 要求 | 落地阶段 |
|---|---|---|
| 限流 | 单 IP 创建接口 20 次/分钟；跳转接口按短码 5000 QPS | W5 |
| 缓存 | 短码 → 长链，TTL 24h + 随机抖动（防雪崩） | W2 |
| 缓存穿透 | 布隆过滤器拦截不存在的短码 | W3 |
| 日志 | 请求日志含 `traceId`，异常日志带堆栈 | W7 |
| 监控 | `/actuator/health`、`/actuator/metrics` 可访问 | W7 |
| 敏感信息 | 不把堆栈返回给前端 | W1 |
