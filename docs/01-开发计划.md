# 高并发短链平台 · 开发计划

> 目标：Java 后端**日常实习**的简历项目。
> 核心不是"功能多"，而是"**能被追问 30 分钟**"。

---

## 一、项目定位

| 项 | 内容 |
|---|---|
| 一句话描述 | 面向中小团队的短链服务：短链生成、302 跳转、访问统计、接口限流 |
| 简历技术关键词 | Spring Boot 3 / MySQL 8（索引 + 事务）/ Redis 7（缓存 · 布隆过滤器 · 分布式发号 · Lua 限流）/ 异步削峰 / Docker / JMeter 压测 |
| **不写进项目经历** | Spring Cloud（仅写进"技能"栏的"了解"项） |
| 前端范围 | 2 个页面：创建短链、查看统计。**不追求好看，能跑就行** |
| 预估周期 | 8 周核心 + 1 周部署收尾（按每周 15h+ 估算） |

---

## 二、技术选型

| 层 | 选型 | 版本 | 说明 |
|---|---|---|---|
| 语言 | Java | **17** | Spring Boot 3 的最低要求，别用 8 |
| 框架 | Spring Boot | **3.5.x** | 用当前最新稳定版 |
| ORM | MyBatis-Plus | 3.5.x | 比原生 MyBatis 少写大量样板代码 |
| 数据库 | MySQL | **8.0** | 注意 utf8mb4 下索引长度限制（见 DDL 注释） |
| 缓存 | Redis | **7.x** | 缓存 / 布隆 / 发号 / 限流，四件事共用 |
| 接口文档 | Knife4j | 4.x | OpenAPI 3，调试方便 |
| 构建 | Maven | 3.9+ | |
| 容器 | Docker + Compose | 最新 | 一键起 MySQL + Redis |
| 压测 | JMeter 或 wrk | - | 出"优化前 vs 优化后"对比数据 |
| 前端 | Vue 3 + Vite + Element Plus | - | 只做 2 个页面 |

### 为什么不上 Spring Cloud（这条要记住）

日常实习面试基本不考微服务；单人项目硬拆服务，只会让面试官顺着问出一堆你答不上来的问题（分布式事务、链路追踪、服务熔断……）。

**正确做法**：简历"技能"栏写 `了解 Spring Cloud Alibaba（Nacos / Gateway / OpenFeign）`，**不写进"项目经历"**。等入职后真有场景了再补。

## 四、第 1 周逐日清单

**时间预算**：每天约 2 - 2.5 小时，一周 7 天约 15 - 17 小时。

### Day 1 · 环境与骨架

| 任务 | 细节 |
|---|---|
| 装环境 | JDK 17、Maven、IDEA（社区版够用）、Docker Desktop |
| 起中间件 | 写 `docker-compose.yml`：MySQL 8.0 + Redis 7（端口 3306 / 6379） |
| 建项目 | Spring Initializr：Spring Boot 3.5.x、Maven、JDK 17；依赖勾 Web / Validation / Lombok / MySQL Driver |
| 补依赖 | 手动加 MyBatis-Plus、spring-boot-starter-data-redis、Knife4j |

**验收**：本地 `8080` 起服务，`/actuator/health` 返回 `UP`；`docker ps` 能看到两个容器。
**今天必须想明白**：为什么用 Docker 而不是本地装？（答案：环境和同事/面试官一致，一条命令重建）

---

### Day 2 · 工程分层与统一响应

| 任务 | 细节 |
|---|---|
| 包结构 | `controller / service / mapper / entity / dto / vo / common / config / exception` |
| 统一响应 | `Result<T>{ code, message, data, traceId }`，`code=0` 表示成功 |
| 全局异常 | `@RestControllerAdvice` + 自定义 `BusinessException` + `ErrorCode` 枚举 |
| 参数校验 | 开启 `@Valid`，把 `MethodArgumentNotValidException` 统一转成 `code=400` |

**验收**：造一个抛 `BusinessException` 的测试接口，返回的是统一 JSON 而不是 Spring 默认报错页。
**必须能讲清**：为什么要统一响应体？（前端无需处理多种错误形态；便于加 traceId 做链路排查）

---

### Day 3 · 建表与数据层

| 任务 | 细节 |
|---|---|
| 建库 | 执行 `docs/02-数据库设计.sql` |
| 配置 | `application.yml` 配 datasource + MyBatis-Plus（驼峰、逻辑删除、分页插件） |
| 实体 | `ShortLink`、`LinkAccessLog`、`LinkStatsDaily` + 对应 Mapper |
| 冒烟 | 用 MyBatis-Plus 的 `insert` / `selectById` 往 `t_short_link` 写一条读一条 |

**验收**：能通过 Mapper 完成一条记录的写入与查询。
**必须能讲清**：`uk_origin_url_md5` 唯一索引是干什么的？（**幂等**：同一长链只生成一个短码）

---

### Day 4 · 接口文档与参数校验

| 任务 | 细节 |
|---|---|
| Knife4j | 接入并访问 `/doc.html`，完成分组配置 |
| 注解 | Controller 加 `@Tag` / `@Operation` / `@Parameter`，DTO 加 `@Schema` |
| 校验规则 | 长链格式校验（URL 正则）、长度上限、过期时间不得早于当前 |

**验收**：Knife4j 页面能看到接口定义并可直接调试；传非法 URL 返回统一 `400`。
**必须能讲清**：前端校验和后端校验为什么要都做？（前端可绕过）

---

### Day 5 · 短码生成（核心算法）

| 任务 | 细节 |
|---|---|
| 第一版发号 | `INCR short_link:seq` → 得到自增序号 |
| Base62 编码 | 写 `Base62Util`：序号 → `aB3xK9` 形式的短码 |
| 单元测试 | 生成 10 万个短码，断言无重复、可反解回序号 |
| 对比记录 | 在复盘文档里写清：自增 ID / 随机 / 哈希 / **Redis INCR** / 号段模式 各自优劣，以及你为什么选它 |

**验收**：`Base62UtilTest` 全绿。
**必须能讲清**：为什么不直接把数据库自增 ID 当短码？（可枚举、暴露业务量、泄露增长曲线）

---

### Day 6 · 创建短链接口（打通主链路）

| 任务 | 细节 |
|---|---|
| 主链路 | 参数校验 → 长链 MD5 查重（幂等）→ 发号 → 生成短码 → 落库 → 返回短链 |
| 事务 | `@Transactional` 边界只在写库这一段，**不要把 Redis 调用包进事务** |
| 自定义短码 | 支持用户指定短码（需先查重，冲突返回业务错误码） |
| 并发防护 | 同一长链并发创建时，靠唯一索引兜底 + 捕获 `DuplicateKeyException` |

**验收**：Knife4j 连续两次提交**同一条长链**，返回**同一个短码**。
**必须能讲清**：并发下两个请求同时插同一长链会发生什么？你怎么处理的？

---
